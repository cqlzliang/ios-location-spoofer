# 收藏定位点需求文档

## 1. 背景

`location-picker` 是 iOS Location Spoofer 的配套网页，用于在地图上选择定位点，并通过服务端配置当前生效的模拟位置。

当前网页主要支持：

- 地图选点；
- 搜索地点；
- 自动获取海拔；
- 调整水平精度和垂直精度；
- 保存当前定位；
- 开启或恢复定位伪造。

本需求增加“收藏定位点”能力，方便在常用地点之间快速切换，并可以直接将收藏点应用为当前定位。

## 2. 需求边界

### 2.1 使用模式

- 当前服务只供本人使用。
- 收藏列表为服务实例级别的全局列表，不按 token 或用户区分。
- 保留现有 token 认证机制，用于保护网页和 API。
- 暂不限制收藏数量。

### 2.2 存储要求

- 收藏数据只保存在服务端。
- 不使用浏览器 `localStorage`、`sessionStorage` 或其他本地缓存作为数据源。
- 更换设备、浏览器或清除浏览器数据后，收藏仍应从服务端恢复。
- 第一版只实现 Cloudflare Worker；Node 版后续按相同需求补充，不要求两种部署之间同步。

### 2.3 与当前定位的关系

收藏点和当前生效定位是两类数据；查看收藏点和应用收藏点必须分为两个操作：

- 收藏点用于保存常用位置配置；
- 当前生效定位用于供 `/loc.json` 返回给 Shadowrocket / Loon；
- 用户点击收藏名称时，只在地图上显示并加载该地点；
- 用户点击“应用”后，收藏点才写入当前生效定位；
- 应用成功后，当前伪造状态自动开启；
- 用户仍可单独使用“恢复真实定位”关闭伪造。

## 3. 收藏点数据

每个收藏点至少包含以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 服务端生成的唯一标识 |
| `name` | 是 | 收藏名称，如“家”“公司” |
| `latitude` | 是 | WGS-84 纬度 |
| `longitude` | 是 | WGS-84 经度 |
| `altitude` | 否 | 海拔，单位米 |
| `horizontalAccuracy` | 否 | 水平精度，单位米 |
| `verticalAccuracy` | 否 | 垂直精度，单位米 |
| `address` | 否 | 地点名称或地址 |
| `createdAt` | 是 | 创建时间 |
| `updatedAt` | 是 | 最后修改时间 |

收藏点不包含 `enabled` 字段。是否开启定位伪造继续由当前定位配置负责。

## 4. 功能需求

### 4.1 添加收藏

用户在地图上选中一个定位点后，可以点击“收藏此点”。

处理要求：

1. 检查当前坐标是否有效。
2. 读取当前地图编辑状态中的坐标、海拔和精度参数。
3. 要求用户输入收藏名称。
4. 名称为空时，可使用搜索关键词、地址或坐标生成默认名称。
5. 将收藏保存到服务端。
6. 保存成功后刷新收藏列表并提示成功。
7. 保存失败时提示错误，不能误显示为成功。

### 4.2 查看收藏列表

网页加载完成后，从服务端读取收藏列表；不从本地缓存恢复。

列表建议显示：

- 收藏名称；
- 地址或坐标；
- 海拔；
- 最近修改时间；
- “使用”操作；
- “编辑”操作；
- “删除”操作。

默认按最近修改时间倒序排列。

没有收藏时显示“暂无收藏”。

### 4.3 使用收藏点

收藏列表中需要将“查看”和“应用”分成两个明确的操作。点击收藏名称时只在地图上显示该地点，点击“应用”按钮后才将其设为当前定位。

处理流程：

查看流程：

1. 将收藏点坐标加载到地图；
2. 移动地图图钉；
3. 填充海拔、水平精度和垂直精度；
4. 更新地址或地点信息；
5. 标记为当前网页编辑状态，但不调用当前定位保存接口。

应用流程：

1. 点击收藏列表中的“应用”按钮；
2. 将收藏点数据加载到当前定位请求；
3. 调用当前定位保存接口；
4. 应用成功后刷新当前定位状态，并提示已生效；
5. 应用失败时保留原来的当前定位，并提示错误。

“应用”按钮会直接改变当前生效定位，按钮文案必须明确；收藏名称本身只能执行查看/预览。

### 4.4 修改收藏点

第一版不提供收藏点原地编辑功能。收藏内容需要修改时，用户先删除旧收藏，再重新选择地点并添加新的收藏。

重新添加时的填写方式如下：

- 坐标：只能通过地图点击、拖动图钉或地图选点修改，不能直接输入经纬度；
- 名称：可以手动编辑；
- 地址：可以手动编辑，也可以由选中地点自动填充；
- 海拔、水平精度、垂直精度：随地图选点使用当前页面已有的自动获取或默认值，不作为收藏编辑时的手动文本字段。

修改流程：

1. 删除原收藏；
2. 在地图上重新选择或拖动图钉；
3. 手动填写名称和地址；
4. 点击“收藏此点”；
5. 服务端新增收藏；
6. 刷新列表并提示成功。

重新添加不会自动修改当前生效定位。若要应用新的收藏点，用户需要点击该点的“应用”按钮。

### 4.5 删除收藏

用户可以删除收藏点。

处理要求：

- 删除前需要二次确认；
- 删除成功后刷新收藏列表；
- 删除失败时保留列表内容并提示错误；
- 删除收藏不会影响当前已经生效的定位；
- 删除当前正在编辑的收藏时，应退出编辑状态或提示用户刷新。

### 4.6 重复收藏

暂不强制禁止同一坐标多次收藏。

如果用户收藏相同或接近的坐标，界面可以提示已有相近收藏，但不应阻止保存。是否允许同名收藏也暂不限制。

### 4.7 点选后的地址获取（后续优化）

本项暂只记录需求，不纳入当前版本实现。

当前点选坐标的处理方式：

- Leaflet 直接从地图点击事件中取得经纬度，不调用高德或 OSM 的坐标接口；
- 高德地图图层使用 GCJ-02，页面在本地将其转换为 WGS-84 后保存；
- OSM 地图图层使用 WGS-84，直接使用点击坐标；
- 点击地图或拖动图钉后，当前实现会额外请求 Open-Meteo 获取海拔；
- 地图瓦片、地点搜索和海拔获取仍会产生对应的第三方网络请求。

后续增加逆地理编码后，按当前地图源选择地址服务：

- 使用高德地图或高德卫星图层时，调用高德逆地理编码接口，展示中文地址；
- 使用国外 OSM 图层时，调用 OSM Nominatim 逆地理编码接口，展示英文地址；
- 逆地理编码应使用 WGS-84 坐标，不能把高德图层的 GCJ-02 坐标直接发送给地址服务；
- 只在用户点击地图或拖动图钉结束后请求，不在地图连续拖动过程中高频请求；
- 请求失败时不影响坐标选点、海拔获取和保存定位，地址保持为空或上一次有效值，并提示地址获取失败；
- 查询到的地址展示在当前定位信息区域，同时填入“地址”输入框；收藏时将该地址一并保存；
- 点击收藏名称预览收藏点时，也应展示收藏中已保存的地址，不重复查询；
- 若地址服务没有返回结果，允许用户继续手动填写或修改地址。

服务接入要求：

- 高德 Web 服务 Key 应保存在 Worker 环境变量中，不下发到浏览器；
- Nominatim 公共服务需要遵守其访问频率、User-Agent/Referer 和归属信息要求；
- 逆地理编码应优先由 Worker 代理，以便隐藏高德 Key、统一错误处理并控制请求频率；
- 地址查询不能阻塞 `/set` 保存定位主流程。

## 5. 当前定位功能兼容要求

现有功能必须保持不变：

- 地图直接选点；
- 地图拖动图钉；
- 地点搜索；
- 海拔获取；
- 保存定位；
- 恢复真实定位；
- 当前定位配置通过 `/loc.json` 提供给代理模块。

收藏功能不能改变以下行为：

- 点击地图只预览，不自动保存；
- 点击“恢复真实定位”只改变伪造开关；
- 点击“保存定位”才写入当前生效配置；
- 收藏数据不会被 `/loc.json` 直接返回。

## 6. 异常处理

需要覆盖以下情况：

- 未携带 token：拒绝访问；
- token 无效或服务端认证失败：提示认证失败；
- 收藏名称为空：使用默认名称；
- 坐标无效：拒绝添加或更新；
- 收藏 ID 不存在：提示收藏已不存在并刷新列表；
- 网络请求失败：提示网络错误，不清除当前编辑状态；
- 服务端存储失败：提示保存失败；
- 收藏列表加载失败：显示错误状态，并允许用户继续进行普通地图选点。

## 7. 第一版范围

第一版必须实现：

- 服务端持久化收藏；
- 添加收藏；
- 查看收藏；
- 加载并使用收藏；
- 删除旧收藏后重新添加；
- 删除收藏；
- Cloudflare Worker 版支持；
- 不使用本地缓存；
- 不限制收藏数量；
- 不做用户/Token 级收藏隔离。

第一版暂不要求 Node 版支持。Node 版可以在 Worker 版稳定后按同一套功能补齐。

第一版暂不实现：

- 收藏分组；
- 收藏排序拖拽；
- 收藏导入导出；
- 收藏分享；
- 收藏历史版本；
- 收藏原地编辑；
- 管理后台查看或管理收藏。
- 点选后的自动逆地理编码及地址自动填充。

## 8. 验收标准

1. 在浏览器 A 添加收藏，刷新页面后仍能看到收藏。
2. 在浏览器 B 或另一台设备打开同一 Worker 地址后，能看到相同收藏。
3. 点击收藏名称后，地图显示该收藏点，但 `/loc.json` 不发生变化。
4. 点击“应用”后，`/loc.json` 返回该收藏点坐标，且伪造状态自动开启。
5. 修改收藏时，删除旧收藏后可以重新添加新收藏。
6. 删除收藏后，列表中不再显示该点。
7. 删除收藏不会改变当前已经生效的定位。
8. 清除浏览器缓存或禁用 `localStorage` 不影响收藏功能。
9. 所有服务端异常都能在页面显示明确提示，不出现“操作实际失败但页面显示成功”的情况。
